# LitAgent v4 阅读流程与验收

更新日期：2026-11-15。本次在既有文献库、全文 RAG、笔记和页面基础上增加阅读工作流。v3 的记录保留为当时的历史状态；本次验证结果单独记录在 `VALIDATION_V4.md`。

## 这次实际增加的能力

1. **Skill 参与取证。** 八种阅读模式各有材料提取重点。复现模式重点保留训练参数、数据划分、代码与硬件信息；实验审计关注基线预算、种子和误差报告。复现、审计最多补查两个预设主题，批判评审最多一个。模型只选择预设主题序号，不能新增工具或任意循环。
2. **有范围的连续追问。** 同一阅读会话使用最近三轮成功的阅读问答消解“这个方法”等指代，再在当前论文内检索。历史答案不作为事实证据，旧引用会被移除。切换论文、文档版本或阅读档案会隔离旧上下文；前端可以新建阅读对话。
3. **引用依据自动检查。** 回答生成后，最多检查八个带引用的段落，展示支持、部分支持、证据不足或未核查，以及可点击的原文摘录。服务端检查摘录是否逐字来自本段引用。模型判定仍可能出错，不等于人工审核，也不会自动放行训练样本。
4. **研究档案。** 增加研究方向、可用算力、计划框架和已掌握知识。提供无人机强化学习、Agent 工程、组会准备三种可编辑模板，点击保存才生效。算力约束用于建议，不会被当作论文报告的配置。
5. **材料缓存。** 相同原文、模型和 Skill 取证配置可复用分段提取结果。最终回答仍按本次档案和问题重新生成。关闭“复用已提取的材料”可强制重新提取。
6. **本机启动与运维。** 启动前检查核心依赖、配置和端口；只复用同一数据库与数据目录的本应用服务。提供离线模型检查、数据库与 PDF 备份，以及人工标注驱动的评测脚本。

## 使用

在项目目录执行：

```powershell
.\start_webui.ps1
```

也可以双击 `start_webui.bat`。启动器不会自动安装依赖或下载模型。通常地址为 `http://127.0.0.1:7860`；自定义 `LIT_PORT` 时以启动输出为准。关闭前台启动窗口或按 Ctrl+C 停止服务。只运行一个使用同一数据目录的服务进程。

建议依次验证：

1. 检查“我的文献库”是否仍有原有记录。
2. 选择已处理全文的论文，在阅读档案里选模板，填写自己的算力、知识背景和框架，保存。
3. 选“复现”并开始全文阅读。阶段应包含分段阅读、材料缺口检查、定向补查、生成笔记和引用核查。若没有缺口，不会实际检索补充主题。
4. 检查结果中的论文已报告配置、建议配置和缺失信息是否区分清楚，点击引用对照原文。
5. 切换“证据追问”，问“这个方法在训练时需要哪些信息？”。任务记录中的 `query` 是补全后的检索问题，页面统计包含使用的历史轮数。
6. 切换阅读档案或论文后再追问，确认没有沿用旧档案。新建阅读对话会断开当前浏览器上下文；后台已有任务仍可在任务记录中查看。
7. 同一论文、同一 Skill 再读一次，检查材料缓存命中数。改变档案仍会重新生成回答。修改笔记并保存后，不再对修改版展示原答案的核查结论。

### 两篇论文对比

选择阅读模式“对比”，选文区域会显示“论文 A”和“论文 B”两个独立选择框。分别选择不同论文；下方显示完整标题及全文处理状态。若有论文尚未处理，先点击“处理全文”并等待完成。

选择“全文总结”，填写希望比较的维度，例如研究问题、方法机制、实验条件和适用边界，再点击“开始阅读”。对比模式会阅读两篇论文的材料，要求结果分别引用双方证据；不同数据集、指标和计算预算下的实验数值不能直接用来排名。后续可切换“证据追问”继续比较具体问题。

刷新页面可恢复已完成任务的 A/B 选择。切换回其他阅读模式时保留当前第一篇已选论文。此入口于 2026-11-16 改为独立选择框，不再依赖原生列表的多选快捷键。

### PDF 原文预览

在阅读工作台点选论文，右侧自动切换到“PDF 原文”；点击“阅读笔记”可返回已有结果，开始阅读任务也会切回笔记。对比模式选好两篇后，原文区域可用“论文 A / 论文 B”切换，预览切换不改变阅读任务的论文选择。

本地 PDF 直接预览，不要求已完成索引。只有 arXiv 记录时会自动下载并缓存 PDF，后续复用本地文件；此步骤不调用大模型、不加载嵌入模型，也不生成阅读任务。下载失败时显示原因，并提供重试及原文链接。其他来源尚无本地文件时，需要导入 PDF 或打开来源链接。使用随项目提供的 PDF.js 在页面中渲染，无需外部 CDN；支持上一页/下一页、输入页码、缩放、适应宽度和文字选取，右上角可在新窗口打开原始文件。

“我的文献库”和“分类浏览”点选论文后也会在详情顶部显示 PDF。此功能于 2026-11-16 加入。

## 流程、版本与边界

全文阅读：

```text
任务快照 -> 按 Skill 提取逐段证据 / 复用缓存
         -> 检查主题缺口 -> 最多两次限定论文范围的补查
         -> 个性化合成 -> 引用 ID 校验 -> 自动依据检查 -> 笔记
```

追问：

```text
同会话 / 同文档版本 / 同档案的最多三轮问答
  -> 消解指代 -> 混合检索 -> 同页相邻片段
  -> 个性化回答 -> 引用 ID 校验 -> 自动依据检查
```

- 阅读工作流版本为 `reading-v4.1`。任务持久化完整 Skill 指令和取证配置快照，Skill 工作流版本为 `2.0.0`；原 Markdown 指令版本单独保留为 `instruction_version=1.0.0`。
- 缓存键含工作流版本、Skill ID/版本、取证提示词、模型名及完整原文片段。提取阶段不使用个人档案，因此可跨档案复用；合成阶段使用本次档案。删除文档时数据库外键级联删除相应缓存。
- 模型名是服务商别名，无法检测服务商在同名下替换底层模型。需要严格实验时关闭缓存，并保存实验日期及调用记录。
- 全文最多 160 个片段，每批八个。追问检索八个主片段并扩展到最多十四个；补查每主题检索四个主片段并扩展到最多六个。不会把少量检索片段称为阅读全文。
- 阅读任务默认时限 600 秒（`LIT_READING_SECONDS`），其他任务仍为 180 秒（`LIT_TASK_SECONDS`）；文献管理最多十二轮工具调用；模型层另有三十二次调用上限。
- 2026-11-16 起，最终笔记单独使用 8192 tokens 输出预算（`LIT_READING_MAX_TOKENS`），分段取证及其他辅助调用保留 2500 tokens。输出预算不同于输入上下文容量，修改后需要重启服务。长论文仍可能达到预算限制。
- 模型调用记录 `model_response` 事件，包含 `finish_reason`、请求输出预算、实际 Token 用量及耗时，不包含密钥或请求正文。失败任务的 checkpoint 也保留已知用量和最后一次调用诊断；流中断时没有收到用量的字段记为 `null`。
- 长度截断、内容过滤、服务端资源不足和缺失结束标记分别提示。未完整生成的内容不会作为正式笔记保存；重试可复用已完成的分段取证。
- 自动依据检查只覆盖最多八段，过长段落和材料超限会保留未核查状态。剩余时间不足十二秒时跳过核查。数字、因果及范围是否得到原文支持仍需人工确认。
- 生成答案持久化后，核查阶段中断可重试，不需要再次生成整份答案。读取任务可恢复；存在写入副作用的文献管理对话不自动重放。
- SSE 断线重连接受 `Last-Event-ID`，防止重复拼接已显示的生成片段；刷新页面可从持久化任务恢复。
- 仍是 pypdf 文字提取，没有新增 OCR、图像理解或可靠的公式/表格解析。没有训练或部署 SFT 模型。

## 配置诊断与备份

```powershell
.\.venv\Scripts\python.exe -m scripts.maintenance doctor
.\.venv\Scripts\python.exe -m scripts.maintenance doctor --load-model
```

第一条只检查配置与包是否存在；第二条在离线模式加载 E5 并验证 384 维编码。密钥只报告是否存在，不显示密钥，也不通过在线调用验证账户。

备份前等待任务结束并停止服务，保证 SQLite 与 PDF 文件来自一致的时间段：

```powershell
.\.venv\Scripts\python.exe -m scripts.maintenance backup
```

每次写入独立文件夹，包含 SQLite 快照、按哈希保存的 PDF 和 `manifest.json`。只有 `complete=true` 才表示复制及文件哈希检查全部完成。没有复制 `.env`、模型权重或 Qdrant 向量目录。

恢复时先停止应用并保留当前数据库及其 WAL/SHM 文件，再将备份数据库与 PDF 放回实际配置的数据库路径、`data/pdf`。备份未包含向量索引，恢复后必须重新建立全部文档的向量索引，不能仅凭数据库中的 `ready` 状态认定已恢复语义检索。此版本提供备份工具，尚无一键恢复命令。

## 真实评测

本轮提供 `artifacts/eval/questions-20261115.json`，包含十篇真实文献的三十个**待填写**问题位置，不包含虚构问题、标准答案或实测分数。当前只有已建立全文索引的论文可进入检索评测。

也可生成新的模板：

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate_reading init --output artifacts/eval/questions-new.json
```

每篇对应直接问答、综合问答和不可回答问题。人工填写 `question`、`expected_answer`、`reviewer` 后，将 `reviewed` 设为 `true`。可回答问题还需填写 PDF 的 SHA-256、从 1 开始的页码及逐字摘录；文件顶部 `sources` 提供已处理文档的信息，页码/原文可通过引用窗口查看。不可回答问题的 `evidence` 留空，由人工确认论文无法支持该问题。

不要以自动生成的答案作为标准答案。测试库应与调试提示词用的论文分开；这里按库中记录生成的模板**并不自动保证未参与调参**，需自行替换或筛选。

启动本机服务后运行：

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate_reading retrieval --dataset artifacts/eval/questions-20261115.json --output artifacts/eval/retrieval-run1.json
```

脚本校验人工标注与当前 PDF 页文本是否一致、服务是否使用同一数据目录，然后比较 keyword、dense、hybrid 三种检索。通过正在运行的服务查询，避免第二个进程占用 Qdrant 本地目录。

- 指标是每个可回答问题的“前五个片段包含多少条标注证据”，再对问题取平均；它不是答案正确率。
- 摘录需要完整落入某个召回片段；跨分块的长摘录会低估命中，应标注简短且完整的证据句。
- 未审核问题被排除并记录；全部未审核则拒绝出具指标。
- 不可回答问题不进入召回均值，需要另外人工检查回答是否正确拒答。
- 报告记录样本量、各问题命中、片段 ID 和请求耗时。首轮耗时可能含模型加载；比较延迟时需记录预热状态。

### 等材料提示词对比

用已成功完成的新阅读任务 ID，先导出干运行材料：

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate_reading pair --task-id TASK_ID --output artifacts/eval/pair-plan.json
```

干运行不调用模型。显式增加 `--allow-model-calls` 才执行两次真实 API 调用，使用相同论文材料、历史、档案、模型、温度和输出预算，比较通用提示与该任务的 Skill 提示：

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate_reading pair --task-id TASK_ID --allow-model-calls --output artifacts/eval/pair-run1.json
```

这只评估**相同材料下的合成提示词**，不能证明整个取证流程更好。结果中的 `generic`、`skill` 是实验标识，不是盲评材料；人工评审前应另行隐藏并随机排列标识。评审事实错误、引用支持、方法解释、实验覆盖和有用性，填写理由，保留差样本。未经评审的结果不产生“质量提升”结论。

所有输出使用新文件名，脚本拒绝覆盖已有报告。输出可能包含个人档案和原文材料，保存在默认被版本控制忽略的 `artifacts/`。
